# RoadTripMovie for Windows

This is the C++/WinRT WinUI 3 desktop application and MSIX packaging project. Open
`RoadTripMovie.sln` in Visual Studio 2022 with the **Desktop development with C++**,
**Windows App SDK**, and **MSIX Packaging** components installed.

The pipeline scans `.jpg`, `.jpeg`, `.png`, `.heic`, `.heif`, `.mp4`, `.mov`, `.avi`,
`.mkv`, and `.m4v` files, sorts them by file modified time, and uses LibFFmpeg to inspect
video duration and audio streams. It renders per-item MPEG-4/AAC segments concurrently
with FFmpeg's in-process C API, adds a pinned OpenStreetMap inset when GPS coordinates
are available, joins the segments without re-encoding, then loops and mixes the selected
music track into the final MP4 in-process. Map tiles and rendered thumbnails are cached
under `.map_cache` next to the output video. The inset includes OpenStreetMap attribution
and requires an internet connection the first time an area is rendered. Segment results
are written to independent files and joined in chronological order. Worker count defaults to the number
of logical processors minus one, capped at four workers (two FFmpeg encoder threads per
segment) to avoid saturating memory and CPU.

## FFmpeg libraries

LibFFmpeg++ (MIT) remains included as a pinned Git submodule and is used for video
inspection. Rendering, joining, and music mixing use FFmpeg's C API directly; no FFmpeg
executable or child process is used. The pinned vcpkg manifest builds shared LGPL FFmpeg
7.1.2 libraries and includes their runtime DLLs in the MSIX next to the app executable.

FFmpeg's native `mpeg4` video encoder and AAC audio encoder are used so that the default
dependency remains LGPL; output MP4 video is MPEG-4 Part 2 rather than H.264. Verify the
FFmpeg license notices and source/relinking information required by the exact build
distributed through the Microsoft Store. Runtime DLLs are generated by vcpkg and are not
checked into this repository.

## Build and publish

1. Initialize LibFFmpeg with `git submodule update --init --recursive`.
2. Install vcpkg and its Visual Studio integration, then run `vcpkg install --triplet
   x64-windows` from `native/` to build the pinned FFmpeg shared libraries.
3. Set `Identity Publisher` in `RoadTripMovie/Package.appxmanifest` to the publisher
   identity from Partner Center.
4. Install your Store signing certificate with its private key in the Windows
   certificate store and run the signing/build script from PowerShell:

   ```powershell
   .\Build-ReleaseMsix.ps1 -CertificateThumbprint YOUR_CERTIFICATE_THUMBPRINT
   ```

   Use `-CertificateStoreLocation LocalMachine` if the certificate is installed in
   `LocalMachine\My`, or `-VcpkgPath` to select a vcpkg executable. The script installs
   the manifest dependencies, builds Release|x64, signs the MSIX, and checks that the
   generated bundle has the requested signature and contains the FFmpeg runtime DLLs.
   The bundle is written under `artifacts/`.

For F5/debugging, set **RoadTripMovie.Package** as the Visual Studio startup project so
the app starts with its MSIX package identity and Windows App Runtime dependency. The
native executable also bootstraps Windows App Runtime 1.6 for direct, unpackaged
launches; those require the x64 Windows App Runtime 1.6 framework and main runtime
packages to be installed.

The script does not download a signing certificate. An MSIX signed with a local
development certificate is suitable for testing only; use the Store-compatible publisher
certificate and submission workflow for publishing.

The initial native UI exposes core render settings. Offline closest-city lookup and its
bottom-center text overlay are not yet implemented in this WinUI port.
